# DA3 Standing Rules

1. Before acting, read `AGENTS.md`, `.agent/CONTINUITY.md` and `docs/da3/DA3_PLAN.md`, then only the source files relevant to the task. If a task conflicts with `DA3_PLAN.md`, the task wins; log the difference in `docs/da3/03-decisions-log.md`.
2. PLAN-FIRST tasks: inspect, then show (a) files to change, (b) the exact change, (c) acceptance criteria, (d) regression risks, (e) new dependencies. Then STOP and wait for my word "approved". Other tasks: implement directly as a small patch.
3. Implement only what is approved. No unrelated refactors. Scripts are Python 3 (use dependencies already in requirements where possible) and must run from Windows PowerShell. Pin Docker image tags.
4. Do NOT run load tests, failover tests, scans or anything long, and do NOT take screenshots, unless the task says so. I run those.
5. Never print or commit secrets (database URLs, JWT/encryption keys, TOTP secrets). No hardcoded absolute paths. Config comes from repo-local gitignored `.env` files, with placeholders in `.env.example`.
6. Never invent, estimate or hand-type results. Every number in a table must be generated by a script from raw files in `docs/da3/results/`.
7. Finish every task with the evidence routine: (a) save raw output to `docs/da3/results/`, (b) generate tables by script, (c) update this part's section in `docs/da3/02-report.md` using its template, (d) add a row to `docs/da3/04-evidence-index.md` for every screenshot I must capture (filename, what it must show, exact command or page), (e) update `docs/da3/01-checklist.md` (`[~]` until evidence exists, `[x]` only when it does), (f) log decisions and reasons in `docs/da3/03-decisions-log.md`, (g) update `.agent/CONTINUITY.md`.
8. End your reply with three lists: files changed; what I must run; what I must capture.
